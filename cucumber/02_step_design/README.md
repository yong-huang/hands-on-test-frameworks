# 02 · 步骤层设计：参数捕获、复用与页面对象收口

> 步骤层是 Gherkin 与浏览器的翻译层，翻译质量决定套件寿命。本实验立三条设计纪律：
> 一步一业务动作、参数捕获替代复制粘贴、定位器收口进页面对象——并用 grep 门禁强制执行。

## Background

lab 01 的步骤层把定位器（getByTestId）直接写在步骤里，三个场景后问题已现：
新场景想"以不同账号登录"，只能整段复制；UI 改版时要在散落各处的步骤里搜替定位器。

专业形态分两层：步骤层只做"句子到业务动作"的绑定，动作的实现在页面对象
（Page Object，把页面的操作与定位封装成类）里完成。这样 UI 改版只动 pages/，
句子措辞调整只动步骤层，互不牵连。

## What

本实验的订单管理特性覆盖创建/同名创建/删除三个场景，步骤层共 8 个步骤定义。
关键机制有两个：Cucumber 表达式的参数捕获（`{string}`、`{int}` 把句子里的值
传进函数），与页面对象的动作委托（步骤调用 `orders.create(title)`）。

可以把步骤层想成前台接待：客人（Gherkin）用自然语言说需求，
接待员（步骤层）听懂后转给对应部门（页面对象）执行。
接待员不亲自修水管——那是部门的专业活。但和前台不同，
cucumber 按"句子全文"匹配步骤定义，两句话只要差一个字就是两个步骤。

## When to Use

| 场景 | 参数捕获 | 每场景复制步骤 |
|:---|:---|:---|
| 同一动作 × 不同数据（登录多账号） | ✅ 一条定义 N 处使用 | ❌ 复制爆炸 |
| 步骤间细微差异（"再创建"） | ✅ 措辞区分 | ❌ 语义混乱 |
| 真正不同的业务动作 | ✅ 各写各的 | ✅ |

判断口径：**两个步骤定义的差异只剩参数时，必须合并**；
措辞不同但语义相同的步骤（"创建"与"再创建"）可以共存，服务于场景可读性。

## How It Works

**Cucumber 表达式是类型化的参数协议。** `{string}` 匹配引号内文本、
`{int}` 匹配整数并转成 number——参数按位置传入步骤函数。
它还承担"发现"职责：feature 里出现未定义的句子时，运行输出会推荐
最接近的表达式写法，照抄即可。

**页面对象管"怎么做"，步骤层管"做什么"。** `orders.create(title)` 内部
知道要先确认页面可见、找到输入框、点按钮、等 POST 响应——这些细节
步骤层一概不知。断言则留在步骤层（`expect(orders.row(title))`）：
页面对象返回定位器，"验证什么"始终是用例的意志。

**动作边界处等待网络确认。** `create()` 在点击后等待 POST /api/orders
的响应才算完成——"click 返回"不等于"数据落库"，这是 UI 测试的经典时序坑。
把等待封装进页面对象的动作里，调用方就永远不会踩到。

**每场景前 /api/reset 回种子。** SUT 是跨场景共享的内存态，
同名订单跨运行累积会让计数断言漂移。

本实验实测踩坑：种子数据里恰有一条"显示器支架"，
与测试造的同名订单撞车，断言提前满足。
Before 钩子里先 reset，是场景隔离纪律的机械保证。

## Pitfalls & Q&A

**Q：`并且 再创建标题为…` 和 `当 创建标题为…` 为什么是两个步骤定义？**
Cucumber 把 And/But 解析为前一个关键字的别名，"并且 再创建…"
实际匹配的就是 `当` 系步骤。

写成独立定义而非复用"创建"，是因为同名双建的语义值得在报告里单独成行。
两条定义内部都调 `orders.create`，实现零重复。

**Q：同名订单场景为什么差点断言假绿？**
种子数据恰好含一条"显示器支架"，测试创建同名订单时
"恰有 2 笔"在只建成 1 条时就满足——实测踩坑。

对策：测试数据用唯一标题（最终采用"显示器支架 PRO"），
或断言前清场（Before 里的 /api/reset）。

**Q：步骤定义里的 {int} 传进来是字符串吗？**
是 number。Cucumber 表达式的 {int} 完成转换后按位置传参，
函数签名写 `count: number` 即可。若用正则捕获则拿到的是字符串，
需要手动 parseInt——这也是官方推荐 Cucumber 表达式优先的原因之一。

**Q：页面对象的 create() 为什么要等 POST 响应？**
click 返回只代表点击事件派发完成，fetch POST 是异步的；
不等响应就返回，下一条断言可能读到旧列表（竞态）。

把 waitForResponse 封装进动作（lab 05 同源思路），
调用方天然拿到"动作已完成"的保证。

**Q：grep 门禁会不会误伤？**
只扫 `features/step_definitions/` 目录的定位器模式（getByTestId 等）。
页面对象目录 pages/ 不在扫描范围。若步骤层确需临时调试，
grep 会当场报文件行号——修完再提交，门禁不设白名单。
