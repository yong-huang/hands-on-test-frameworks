# 04 · 场景大纲：一套骨架吃下任意数据规模

> 登录矩阵有 4 种凭据组合，写成 4 个场景是复制粘贴的开始。场景大纲
> （Scenario Outline）用占位符抽取骨架、用例子表（Examples）承载数据，
> 一套骨架自动展开为 N 次独立执行。本实验踩过两个教科书级坑：
> 方言关键字与占位符引号——都在大纲的解析规则里。

## Background

参数化是测试框架的标配能力：同一流程 × 不同输入 × 不同预期。
@playwright/test 里这叫 test.each，靠数组传参；cucumber 里对应场景大纲
（Scenario Outline）：骨架里的 `<占位符>` 由例子表逐行代入，每组一行
就是一个独立场景，失败定位精确到行。

价值在规模：4 组凭据手工写 4 遍是体力活，40 组就会有人开始"抽象"
步骤内部的 if/else——那是把数据驱动做成了代码驱动。大纲让数据
回归表格，骨架保持业务语言。

## What

场景大纲的执行模型：解析期把 `<占位符>` 按例子表逐行做纯文本替换，
每组展开成一个普通场景（报告中各占一行，独立红绿）。步骤定义侧
用匿名参数 `{}`（或类型化参数）接收代入的值。

可以把大纲想成月饼模子：骨架是模子（花纹固定），例子表是馅料清单
（每行一种馅），压一次出一个饼。但和模子不同，替换是**字面量级**的：
表格里写什么，句子就变成什么——连引号都会原样代入（本实验实测踩坑）。

## When to Use

| 场景 | 场景大纲 | 多个独立场景 |
|:---|:---|:---|
| 同流程 × 多输入 × 同断言模式 | ✅ 主战场 | 复制粘贴爆炸 |
| 每组需要不同的断言步骤 | ⚠️ 骨架容纳不下 | ✅ 各写各的 |
| 业务上确属不同规则 | ❌ 硬塞进表格会失真 | ✅ |
| 输入本身是结构化表格 | ⚠️ 见 lab 05 DataTable | — |

判断口径：**组与组之间只有数据差异时用大纲**；断言行为都不同就别硬凑。
表格列数应该是稳定的业务字段，不是"第 7 列放点特殊逻辑"的补丁位。

## Quick Start

```bash
cd cucumber/04_outline_examples
./outline_examples.sh          # apply 起靶场 → observe 登录矩阵 + 失败定位 → clean
```

observe ① 登录矩阵：1 个大纲 × 4 组例子 = 4 次执行全绿：

```
2 hooks (2 passed)
4 scenarios (4 passed)
20 steps (20 passed)
```

observe ② 是定位能力演示：把第 3 组密码故意改错一位重跑，红行的标题
直接点名是哪一组：

```
✘ 以 admin/wrong-pass-x 登录应 失败
>>> 报告将失败定位到「以 admin/wrong-pass-x 登录应 失败」这一组例子 ✓
```

验收方式：4 组全绿；变异后失败行精确落在本组（不牵连其他组）；
恢复后复跑全绿。

## How It Works

**展开是纯文本替换。** `<占位符>` 的值从例子表原样代入句子——
表格值不带引号，句子就该不带引号；表格值带引号，代入后句子也带引号。
本实验实测踩坑：步骤行写成 `包含 "<关键文案>"`，代入后断言期望
`"用户名或密码错误"`（带引号），与页面实际文本（无引号）必然不等。

**{string} 只匹配带引号的文本。** 步骤定义若写 `{string}`，它要求
句子里对应位置是 `"..."` 的带引号形式——Outline 代入的裸值
（成功、失败、admin）匹配不上。

解法是匿名参数 `{}`：匹配任意文本（不含换行），值原样传入。
规则记法：{string} 对应带引号的句子，{} 对应裸值。

**方言关键字要查表。** zh-CN 方言里场景大纲的关键字是"场景大纲"
（不是"场景模板"！），例子表的表头是"例子"。

写错关键字时 Gherkin 不报错——整段被当作描述文本静默跳过，
表现就是 0 scenarios（实测踩坑）。关键字以 gherkin-languages.json
为准，勿凭印象翻译。

**失败定位是按组报销的。** 每组例子是独立场景：一组红不影响其他组继续跑，
报告直接引用该组的标题（含代入值）。修复时先读红行标题里的参数值，
就能精确复现。

## Pitfalls & Q&A

**Q：占位符两边要不要加引号？**
不要——除非句子语义本身需要引号字符。大纲是字面替换，
`包含 "<关键文案>"` 代入后连引号一起进入断言，
比无引号的页面文本必红（实测踩过，修复即删引号）。

**Q：{string} 和 {} 到底怎么选？**
{string} 匹配**带引号**的文本并把引号剥掉传入；{} 匹配任意非换行文本
原样传入。数据驱动场景里表格值通常不带引号，所以大纲配套的多是 {}；
交互式的手写句子常带引号，适合 {string}。选错的表现就是"步骤未定义"。

**Q：场景大纲的关键字写"场景模板"为什么不行？**
zh-CN 方言表里该关键字是"场景大纲"与"剧本大纲"——"场景模板"不在表内，
整段被当描述文本静默跳过（0 scenarios，无报错，本实验实测踩坑）。
认字不靠翻译，靠 gherkin-languages.json。

**Q：一组例子失败，后面的组还跑吗？**
跑。每组是独立场景，互不牵连——这正是"失败定位到组"的前提。
fail-fast 语义在 cucumber 里由 `--fail-fast` CLI 显式开启，
默认关闭以保证全矩阵反馈。

**Q：Examples 能有多张表吗？**
能。一个场景大纲下可以有多张例子表（常配合标签区分：冒烟一组、
全量一组），运行时按表顺序逐组展开。表间列名必须一致。
