# 02 · 负载建模：开放 vs 封闭模型——你的 P95 可能是压测器替 SUT 隐瞒的

> 基线实验用 5 VU 冒烟，稳定但保守。这一篇把负载当变量做实验：同一套请求
> 动作，分别用**封闭模型**（VU——Virtual User，压测器里持续发请求的虚拟用户——数量固定，等响应才发下一单）和**开放模型**
> （到达率恒定，请求互不等待）压同一个 SUT。同吞吐下 P95 差出 3.6 秒
> ——这就是 Coordinated Omission，性能领域的经典陷阱。

## Background

压测报告的可信度取决于「压力是怎么发出去的」。最常用的封闭模型
（固定并发用户数）有个隐藏缺陷：VU 是"有耐心的用户"——SUT 变慢它就
自动少发请求，压测机成了 SUT 的节流阀，排队被藏起来，P95 被**系统性
低估**。

真实用户没有耐心：页面卡住只会再开一个标签页、再点一次按钮——
生产流量的本质是开放模型（请求按到达率涌来，互不等待）。用封闭模型
的读数做容量决策，等于用被美化的数据做决策。

Coordinated Omission（CO，协同遗漏）是 Gil Tene 对这一现象的命名：
压测端与 SUT"合谋"跳过了本该发出的请求——响应慢 → VU 下一单晚 →
高延迟样本根本没机会产生。

## What

负载建模是把「生产流量长什么样」翻译成压测执行器参数的过程。
两种基本模型：

- **封闭模型（closed）**：VU 数是旋钮，每 VU 等上一个响应完成才发
  下一单——吞吐随 SUT 变慢自动下降。
- **开放模型（open）**：到达率是旋钮（恒定 it/s——每秒启动的迭代数，一次迭代就是一组请求），请求按节拍涌入，
  该排队就排队——SUT 变慢时延迟与错误率如实上涨。

可以把两种模型想成两种客流：封闭模型是"门口只放 100 位顾客、
一位结完账才放下一位"（顾客自备耐心）；开放模型是"门口每秒来 N 人、
排队排到街上"（真实世界）。但和排队的区别在于，封闭模型的"顾客"
永远不会不耐烦走掉——这正是它瞒报延迟的根源。

**结论写进报告模板：容量结论以开放模型为准，封闭模型用于观察并发行为
特征**（比如 VU50→VU100 的 P50 翻倍揭示了线程池排队）。

## When to Use

典型场景：

- 容量评估：开放模型多档加压找吞吐天花板与延迟拐点。
- 并发问题诊断：封闭模型 VU 阶梯放大连接池耗尽、锁竞争、线程池排队
  ——它们对并发数敏感。
- 尖峰演练：30→400→30 it/s 的 spike 场景复现"大促开抢瞬间"。

何时不用：冒烟验活用小负载封闭模型就够（基线实验的场景）；
生产流量无法用到达率近似（强会话绑定、严格串行链路）时，
先建模再压。

- **吞吐天花板 ≈170 req/s**：三档高负载殊途同归，这就是靶场当前的真实

- **同吞吐配对**：~170 req/s 下封闭 P95=750ms、开放 P95=4337ms——

- **Locust 交叉验证**：50 VU 读数与 k6 VU50 同量级

## How It Works

**同一动作、只换执行器**。k6 引擎跑完全相同的三连击（浏览+详情+半概率
下单），只换执行器：封闭档位 VU=10/50/100，开放档位 50/150/300 it/s。
SUT 一变慢，两条路的命运分岔——封闭自节流、开放真排队。
这是对比实验的控制变量法：动作与 SUT 全同，唯一的自变量是执行模型。

**Coordinated Omission 的机制**。响应慢 → VU 下一单晚 → 高延迟样本
缺失 → P95 被低估。对策：开放模型（恒定到达率）+ 记录"应发未发"的
补偿样本。实测表里同一吞吐（~170 req/s）下的 750ms vs 4337ms
就是 CO 的直接证据。

**思考时间的分界**。封闭模型要加思考时间（模拟真人节奏，否则并发 =
纯 back-to-back 打满）；开放模型不加（节奏由到达率负责，迭代内 sleep
只会让"到达"名不副实——本实验 closed.js 有 sleep、open.js 刻意没有）。

## Pitfalls & Q&A

踩坑清单：

- **开放模型里加思考时间**。现象：实际到达率远低于目标。
  解法：节奏全部交给到达率，迭代内不放 sleep。
- **preAllocatedVUs 不够**。现象："到达率恒定"变成 VU 不够的自我设限，
  CO 从反向再骗你一次。解法：VU 池按目标 rate × 预估响应时间估算。
- **Locust 分位数二次换算**。现象：数字差 1000 倍。
  解法：Locust 的 CSV 分位数单位就是 ms，别动它；`--csv` 产物认准
  `_stats.csv` 里的 Aggregated 行。
- **用封闭模型读数做容量结论**。现象：容量被系统性高估。
  解法：容量结论以开放模型为准，封闭只看并发行为特征。

深入问答：

- **Q：什么是 Coordinated Omission？**
  压测器因 SUT 变慢而协同式地少发请求，高延迟样本缺失，P95 被低估。
  对策：开放模型（恒定到达率）+ 补偿样本。
- **Q：封闭模型还有什么用？**
  并发行为特征：连接池耗尽、锁竞争、线程池排队都对并发数敏感，
  VU 阶梯是放大它们的可控手段。
- **Q：吞吐天花板怎么读出来的？**
  多档加压后 RPS 不再增长（169.9→169.7→169.6）而 P95 直线上涨，
  即进入饱和区；天花板数值就是当前架构的容量。
- **Q：压测时该用思考时间吗？**
  封闭模型要加（模拟真人节奏）；开放模型不加（节奏由到达率负责）。
