# 16 · 🏁 API 回归套件

## Background

接口回归的全集 = 正向覆盖 + 异常矩阵 + 结构契约 + **状态机全流转**。前三者前几个实验
都练过，收官时把它们拼成一件武器，并复用项目 11 的 ShopLibrary（造轮子的价值在此兑现）。

## What

- **21 条用例**（验收 ≥20）：正 07（字段完整/金额/回读/中文/特殊字符）+ 异 10
  （422×3 / 404×4 / 409×3）+ Schema 2 + 状态机 2
- 状态机全流转：创建→支付→再支付409→取消409→终态 paid；创建→取消→再取消409→终态 cancelled
- ShopLibrary 复用：生成订单号前缀、生成测试数据（唯一后缀）、金额校验
- 顺带修靶场真 bug：**重复 cancel 未被 409 拦截**（幂等取消口径与状态机预期不一致）

## When to Use

- 发布门禁的 API 层：一条命令、21 条用例、四类保障
- 服务端状态机改版后的全量回归

## How It Works

- 资源文件分层：`api_keywords.resource` 承载请求/断言细节（创建/查询/支付/取消/负向一格/Schema 校验）
- 「负向一格」模板关键字从项目 9 平移——回归套件是既有资产的组装
- 状态机用例把「合法转移 + 非法转移」写进同一条用例，走完即闭环

## Pitfalls & Q&A

- **坑：靶场行为与测试预期的分歧要判责任**——重复 cancel 返回 200 是**靶场 bug**
  （状态机允许从 cancelled 再 cancel，业务上说不通）；修服务端而非放宽断言，
  这是回归套件「抓到真问题」的价值时刻
- **Q：为什么 Schema 组只有 2 条？** 结构契约的细节覆盖在负向矩阵里已隐含
  （每格都断言 error 字段）；Schema 只验证「正向结构合法 + 引擎确实在拦」
