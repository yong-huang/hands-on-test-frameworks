# 🏁 20 · 左移流水线全景：19 个实验 · 一条链跑完

> 建了 6 个阶段 19 个实验——可测性审计、TDD、变异测试、反模式检测、
> 分级门禁、SAST、供应链扫描、性能预算……每个都独立可跑，但它们串起来
> 是什么样子？本实验用一条 `./run_all.sh` 回答：6 个阶段检查器串联 +
> 一个 float 缺陷注入演示（编码层 ~2min 拦截 vs 生产层 ~480min）+
> 一页左移方案书。

## Background

之前的做法：19 个实验各跑各的，没有一个地方能看到「整套体系长什么样、
一个缺陷从需求到生产要经过哪些闸门」。

痛点的核心是**体系缺一个入口**：新同事想看左移全貌，要翻 19 个 README；
汇报要讲 ROI，要手动拼 6 个实验的数字。本实验把散珠串成链——一条命令
跑完全景，一页方案书拿去汇报。

## What

左移流水线全景是一条串联演示流水线：依次调用项目 02（可测性审计）、
10（反模式）、11（分级门禁）、13（供应链）、01（成本漏斗）、15（防
复发规则库）的核心检查器，并注入一个 float 金额缺陷演示「最早拦截点
分析」——每个阶段标明检查器名称与拦截证据。

可以把全景想成工厂的总装线：每个工位（实验）做自己的检查，总装线
（本实验）把它们串起来，最后出厂检验（方案书）交钥匙。但和工厂不同的
是，这条线的「产品」不是物理件——是「哪些缺陷在哪个阶段被拦下」的证据链。

## When to Use

- 新人入门：一条命令看左移全貌（各阶段做什么、产出什么）。
- 汇报展示：方案书 + 缺陷注入演示，用数据讲左移价值。
- 何时不用：不是 CI/CD 流水线（它不自动跑，是演示脚本）；不是
  生产环境工具。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 逐个实验跑 | 灵活但无叙事 | 深入学某个实验 |
| 本实验（全景串联） | 一条链跑通叙事 + 注入演示 | 新人入门/汇报展示 |
| architect/27 效能看板 | 面向全仓库治理 | 更大范围的效能度量 |

## Quick Start

前置：各前序实验的依赖（ruff/mypy/pytest/semgrep/pip-audit）。一条命令：

```bash
./run_all.sh
```

## How It Works

**串联是 cd + 调兄弟脚本**：每个阶段 `cd` 到对应实验目录，跑其核心
检查器，收集退出码，`cd` 回来——没有复杂的编排框架，就是 bash 顺序
执行加结果收集。

**缺陷注入是叙事不是代码**：⑦ 步的缺陷旅程是文本演示（不是真的注入
代码跑一遍）——因为「注入 → 逐层检测」在真 CI 里由各实验独立完成，
串联脚本只负责把故事讲清楚。

## Pitfalls & Q&A

- **路径必须用 `$SL/NN_xxx`**：SL = shiftleft/ 目录；用 `$REPO/NN_xxx`
  会指到仓库根（没有 NN_xxx 子目录）。
- **部分实验有副作用**：11 会写 reports/、13 会调网络——串联前确认
  各实验可以独立运行（不需要 Docker/网络）。

Q&A：

- **和 architect/27 什么关系？** 27 做全仓库治理效能看板；本实验做
  左移线内部的串联演示——规模不同，互不替代。
- **为什么只有 6 个阶段？** 本系列 20 个实验归入 6 个阶段（需求→设计
  →编码→提交→CI→度量）；有些实验（如 01 成本漏斗）是横切度量工具
  而非阶段闸门，所以不在串联主路径上。
