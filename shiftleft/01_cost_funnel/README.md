# 01 · 缺陷成本漏斗：给「测试左移」算一笔账

> 测试左移（Shift-Left Testing，把缺陷发现尽量提前到生命周期左侧）最常被问的不是
> 原理，而是「多建这些检查值得吗」。本实验把同一个金额缺陷放进从需求评审到生产
> 对账的六个关卡，逐关实测拦下它的成本：六关全部拦截，最左 vs 最右杠杆 96×。

## Background

没有这笔账之前，「要不要左移」只能引用业界报告——那是别人的数字，回答不了
「先补单元测试还是先上静态扫描」。

痛点的核心是**检出成本随位置恶化**：同一个缺陷，评审会上拦下只是纠正一张计划表，
生产上拦下是一整条值班排查链。本实验注入一个真实缺陷（金额用 float 计算），
构造六个检测关卡逐关真实运行，产出可抽查复算的成本漏斗表，让数字代替立场。

## What

缺陷成本漏斗是一种量化实验方法：把**同一个缺陷**放到生命周期的六个位置，分别用
该位置的典型检测手段拦截，统计每关的检出成本，得到「越左越便宜」的账；拦截依据
来自需求文档的验收条件（AC，Acceptance Criteria）与既有测试资产。

可以把漏斗想成机场安检：同一件违禁品，出发大厅查出重新打包即可，登机口查出要
拖行李折返，落地查出行李已经上飞机。但和安检不同的是，缺陷的代价主要是人的排查
时间——成本 = 人工分钟（估算）+ 自动化时长（实测）；六关的手段见下图节点副标签。

## When to Use

典型场景：

- 推动左移的立项汇报：用自己仓库复现的 96×（而非业界报告）为检查工具要预算。
- 检查建设的性价比排序：六关杠杆（480× 到 1×）直接回答「先建哪道」。
- 给新工程师建立直觉：为什么「先写失败测试」比「上线靠对账兜底」便宜两个数量级。

何时不用：单缺陷样本的结论是数量级示意而非统计结论；人工分钟是估算，别当财务审计口径。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 业界缺陷放大率报告 | 大样本统计，数字无法本地复算 | 引用行业基准 |
| 生产事故复盘 | 真实，但只有最右端一个点 | 已发生损失的定责定损 |
| 本实验漏斗 | 单缺陷六关全链实测，本地可复算 | 团队要自己的账 |

## How It Works

**缺陷本体只有一处差异**：pricing_good.py 与 pricing_bad.py 业务逻辑完全相同，
差别只在数值类型。这正是这类缺陷难缠的原因——代码评审逐行看都「对」：

```python
total += Decimal(str(p))            # good：十进制精确，19.99 就是 19.99
total += float(p)                   # bad：IEEE-754 二进制浮点，19.99 无法精确表示
```

Decimal("19.99") + Decimal("80.10") 永远等于 100.09，float 的同款算式是
100.08999999999999。脏值顺着调用链扩散：单测红 → 接口响应脏 → 回执肉眼可见。

**六关的检出手段对应真实团队的六种视角**：

- 预防层（关卡 1）：检查测试计划而非代码——AC-2（精确到分）在 test_plan.yaml
  无用例覆盖，评审会当场要求补齐，缺陷进不了编码。
- 编码层（关卡 2/3）：pytest 用字符串断言 `str(total) == "80.09"` 把验收条件
  直译成断言；静态规则 MONEY-FLOAT 用 ast 模块（Python 标准库语法树解析器）
  扫 float 字面量与 float() 调用，违规行号直接给出。
- 测试层（关卡 4/5）：黑盒 HTTP 测试（黑盒＝不读实现代码、只看请求与响应）——
  一个检查响应里的 total，另一个走完整用户旅程校验用户可见文本；E2E
  （end-to-end，端到端）指的就是后一种。
- 生产层（关卡 6）：日结逐笔对账——系统册（本系统记账留下的原始计算值）与
  支付册（支付渠道按分结算后的值）要求零差异。

**成本模型的算账规则**（报告尾部附复算式，每个数字可抽查）：

```text
合计分钟 = 人工分钟（估算，configs/costs.yaml）+ 实测自动化秒 ÷ 60
杠杆     = 生产关合计 ÷ 本关合计        # 最左 vs 最右 = 480.0 / 5.0 = 96×
```

人工分钟是估算、自动化秒数是真实计时；结论看数量级，不看个位数。

## Pitfalls & Q&A

常见故障与解法：

- **端口残留打到旧实现**：孤儿 uvicorn 占着 8931/8932 时，`--impl good` 却输出
  脏值。解法：先 `./cost_funnel.sh clean` 摘端口。
- **断言写成 `total == 80.09`**：float 恰好显示为 80.09 的场景会骗过数值断言；改字符串比对 `str(total) == "80.09"`。
- **关卡 1 在对照组也拦截**：它查的是测试计划完整性，与实现无关，good 模式下
  依然报 AC-2 无用例——设计如此，不参与零误报统计。

Q&A：

- **估算出来的账，可信吗？** 估算透明可复算：改 costs.yaml 任何数字重跑，杠杆
  立即变化；换成团队排查历史，就是团队自己的账。
- **六关全部拦截说明什么？** 每层都有检出能力；要回答的是「希望它在哪层被拦」
  ——先建杠杆最高的那道（本实验是静态规则，1 分钟 vs 480 分钟）。
