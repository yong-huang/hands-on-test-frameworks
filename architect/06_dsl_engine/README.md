# 06 · YAML DSL 接口用例引擎：降门槛的代价算得清吗

> 「让业务同学也能写接口用例」是每家测试平台都要回答的需求。本实验把 httprunner 的
> 思想做成 mini 版引擎：YAML 声明用例（变量/提取/断言），引擎执行并**把失败定位到
> YAML 行号**——平台用户不读 traceback。做完这个实验，「DSL 还是代码写用例」这道
> 面试权衡题就不再是背答案。清单第 6/28 项。

## 1. 为什么需要它

- 10 条接口冒烟用例，DSL 层 74 行 vs pytest 等价 211 行（见 §3 实测）——**行数确实省**；
- 但 DSL 只覆盖声明式场景：复杂流程控制（条件/循环/跨服务编排）在 YAML 里会变成
  图灵完备的噩梦——**边界在哪，做完才知道**；
- 平台化前必答题：报错给用户看什么？`cases.yaml:17` 和 40 行 traceback，是两种产品。

心智模型一句话：**一条用例 = 替换变量 → 发请求 → 提取回写 → 逐条断言**；
extract 写回会话级变量字典（本用例建的 order_id，后续用例直接用）——这正是接口
用例「链式」的本质。

## 3. 快速开始

```bash
cd architect/06_dsl_engine
./dsl_engine.sh apply     # 起 SUT(:8899)
./dsl_engine.sh observe   # 10 条 DSL 全绿 → 变异断言看行号定位 → 行数对比
./dsl_engine.sh clean
```

## 4. 核心概念

### 4.1 会话级变量与类型保留
`${order_id}` 整串引用变量时保留原始类型（int），混在长字符串里才 str 化拼接——
否则 `$.json.id == "${order_id}"` 会变成 `3 == "3"` 永假。**类型语义是 DSL 引擎的
隐形地基**，httprunner 文档里很少讲，做一遍才知道。

### 4.2 响应信封与迷你 jsonpath
响应统一装进信封：`$.status_code / $.headers.*(全小写) / $.json.* / $.text`，
提取与断言共用一个 `$.a.b[0]` 迷你解析器。刻意不引 jsonpath-ng：依赖越少，平台越好部署。

### 4.3 行号定位：DSL 的产品力所在
断言失败时在 YAML 原文里反查 `name:` 所在行，报错格式固定为
`文件:行号（用例名）+ 实际 vs 期望`。引擎内部异常（连接拒绝等）同样归位到用例行号——
**用户永远不需要看 Python 栈**。

## 5. YAML 关键字段

| 字段 | 作用 | 坑 |
|:---|:---|:---|
| `variables` | 会话级变量表，支持 `${__uuid}` | 全局一个 uuid：同用户贯穿全链路是特性不是 bug |
| `extract` | 响应 → 变量（写回共享字典） | 忘了会话级语义，用例间就传不了值（本次踩过） |
| `validate.eq` | `[路径, 期望值]`，类型敏感 | 期望值写 `200`（int）不是 `"200"` |
| `$.headers.x-total-count` | 头键全小写进信封 | 大小写敏感查 `X-Total-Count` 会 KeyError |

## 7. 深入要点

**Q1：DSL 省了 137 行，代价是什么？** 三笔账：表达力上限（复杂编排写不了或写得难看）、
调试体验（引擎报错隔了一层，依赖行号定位做产品补偿）、引擎本身的维护成本（本实验 180 行
只是最小集）。用例少用代码，规模大了上平台——边界由团队构成决定，不由技术审美决定。

**Q2：和「低代码测试平台」什么关系？** 本引擎就是平台的心脏：cases.yaml 换成表单存储、
行号定位换成页面高亮、CLI 换成调度器——平台是 DSL 的产品化外壳（面试讲清这层，
「从 0 到 1 搭测试平台」就有骨架了，对应清单项目 27 的全景）。

**Q3：为什么断言集只有 eq/contains/len_le/exists 四个？** 断言集是 DSL 的「标准库」，
每加一个都有文档/测试/用户心智成本。按「用例里 90% 的断言模式」设计最小集，
长尾需求留给 hook（后续可加 `python:` 扩展点），别把 DSL 变成差劲的编程语言。

**Q4：类型保留为什么值得单独讲？** YAML 一切皆字符串的直觉会让 `qty: "2"` 发给
Pydantic 后端仍能过（强转），但断言侧 `3 == "3"` 永假——**同一份宽松在请求侧无害、
在断言侧致命**。引擎的 fullmatch 类型保留是把这些坑一次性埋掉。

**Q5：失败定位到行，那用例执行到一半断言挂了，后面的断言还跑吗？** 本引擎 fail-fast
（一条用例首个失败断言即停）——定位清晰优先于断言齐全。要「全量断言收集」的平台语义，
把 `run_validate` 的短路改成收集即可，这是一行改动的产品决策。

## 8. 总结

74 行 YAML 换 211 行 pytest，失败定位到行号，引擎只有 180 行——DSL 的收益和边界
这次都是量出来的。当用例规模、编写人群、维护方式三者变化时，「DSL 还是代码」的答案
会自己浮现。下一篇是清单项目 7「测试数据工厂与自清理」：每个团队都被「环境数据越跑
越多」羞辱过，这次让它有解。
