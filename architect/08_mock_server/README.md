# 08 · 录制回放式挡板服务：让第三方依赖在磁带里复活

> 第三方支付、风控、短信——不稳定、要收费、还常常没有测试环境。服务虚拟化的答案是
> **录一次真响应，之后离线确定性回放**。本实验用纯标准库实现挡板三模式（录制/回放/
> 假上游），实测：杀掉真上游断网后，回放输出与录制时逐字节一致；磁带手工改成超时后，
> 客户端正确走进 PENDING_RETRY 降级分支。清单第 8/28 项。

## 1. 为什么需要它

- **依赖第三方做测试 = 把发布节奏交给别人**：对方限流/故障/改版，你的流水线跟着红；
- **联调环境排队**是测试环境问题（01 审计的端口蔓延发现）的常见根源——挡板把外部依赖
  从环境矩阵里摘掉；
- **异常路径难造**：支付网关超时、返回 502 的场景真实世界等不来，磁带编辑一秒模拟。

心智模型一句话：**录制期是代理（转发+落磁带），回放期是数据库（查磁带即答）**；
磁带是普通 JSON——可读、可 diff、可手工编辑成超时/异常，命中统计让挡板的可信度可度量。

## 3. 快速开始

```bash
cd architect/08_mock_server
./mock_server.sh apply     # 起假支付网关(:8900) + 录制模式挡板(:8901)
./mock_server.sh observe   # 录制 → 杀上游断网 → 回放对比 → 统计 → 磁带改超时
./mock_server.sh clean
```

实测输出（节选）：

```
① 录制：支付创建: 订单=ORDER-FIXED-001 txn=TXN-6410053a status=ok / 状态查询 settled
   磁带：GET / → 200，POST /pay → 200，GET /pay/status?txn=… → 200
② 断网：杀掉真上游，挡板切回放模式
③ 回放：结账输出与录制时逐字节一致 ✅
④ 统计：{hits: 2, misses: 0, recorded: 3}
⑤ 磁带标记 POST /pay 超时后重跑：
   支付创建: 订单=ORDER-TIMEOUT-002 → 网关 504
   降级分支: ORDER-TIMEOUT-002 标记 PENDING_RETRY（等待人工/定时补偿）
```

## 4. 核心概念

### 4.1 磁带（cassette）是数据不是代码
`{"POST /pay": {status, headers, body, recorded_at}}`——可 diff 可版本管理可手工编辑。
「标记超时」只是给磁带条目加个 `timeout: true`，回放器延迟后回 504。**挡板的能力边界
写在数据里，不是代码里**。

### 4.2 未命中必须响亮
回放查不到磁带条目时返回自造的 **599**（不是猜一个默认响应）——静默兜底会让「磁带过期
了」变成最难查的灵异失败。响亮的未命中 + 命中率统计，让磁带腐化可被发现。

### 4.3 客户端的降级分支是验收对象
挡板演示的终点不是「挡板能回放」，而是**业务代码对异常响应的反应正确**：支付超时 →
PENDING_RETRY 而不是崩溃。录制正常流是第一步，编辑磁带造异常流才是测试的正文。

## 5. 关键设计

| 设计 | 为什么 | 坑 |
|:---|:---|:---|
| key = `METHOD + path` | 最简命中语义 | 带 query/动态 id 的 path 需要归一化（本版刻意不做，见 §7 Q3） |
| 响应体存原始字节 | 回放逐字节一致 | 存解析后的对象会丢字段顺序/精度 |
| 统计每次落盘 | 服务无状态化，脚本随时读 | 内存统计随进程死掉，断网演示就看不到数了 |
| 脚本 apply 先清残留端口 | 上次中断的服务会占住 8901 | 服务类实验的通用坑：清场永远在启动前 |

## 7. 深入要点

**Q1：挡板、testcontainers、契约测试怎么选？** 依赖是「我方的」且容器化成熟（DB/队列）
→ testcontainers（真依赖、真协议）；依赖是「他方的」稳定且要测我方集成 → 契约测试
（对齐双方预期）；依赖是他方且不稳定/要钱/无环境 → 录制回放挡板。三者是谱系不是对立。

**Q2：磁带会撒什么谎？** 录制时的响应未必永远合法：第三方改了状态码语义、证书轮换、
幂等键过期——所以磁带要带 `recorded_at`，定期重录；关键依赖不能只有磁带，要有真实
联调的抽查（挡板是降级方案，不是终身方案）。

**Q3：动态响应（每次 txn 都不同）怎么录？** 本版 key 是精确 path，回放的 txn 是录制时
那个——确定性回放的代价。生产级方案要加响应模板化（把 txn 抽成变量）与 path 归一化
（`/pay/status/.*` 正则命中）。刻意不做的能力要写进 README，这是工具的诚实。

**Q4：为什么不用现成的 VCR/wiremock？** 会用工具是 labs 的事（labs/14 类似）；造一遍
才懂「命中语义、超时磁带、未命中策略」这些设计点的取舍——这正是平台设计题要的判断力。
工具选型题（Q1）答完后补一句「我造过，知道深浅」是降维打击。

**Q5：磁带入库 git 吗？** 入。磁带是测试资产：可评审、可 diff、改动有迹可循。但注意
磁带里的敏感字段（token/手机号）要在录制时脱敏——否则资产变泄密源。

## 8. 总结

录一次、断网放、统计命中率、磁带造异常——外部依赖从此可控、可重复、可造故障。
挡板与 testcontainers/契约测试的选型谱系，是「第三方依赖怎么测」这道必考题的完整答案。
