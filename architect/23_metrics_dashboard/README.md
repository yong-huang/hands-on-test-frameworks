# 23 · 质量度量体系与看板：「你们质量怎么度量」的一页纸答案

> 「你们团队质量怎么度量？」是架构师面试的必考开放题，大多数人答「看缺陷数和覆盖率」
> 就停了。本实验给出带三要素的答案：每个指标有**公式**（防口径之争）、**来源**
>（可抽查核对）、**反 gaming 说明**（防指标造假）。实测：6 个指标从兄弟项目产物
> 采集，抽查 3 项全部与原始产物一致；数据缺失时看板明示缺失而不是编数。
> 清单第 23/28 项，非功能篇收官。

## 1. 为什么需要它

- 没有度量体系的质量改进是玄学：不知道基线，就证明不了「变好了」；
- 坏指标比没指标更糟：单一缺陷数考核催生「不报缺陷」，单一覆盖率考核催生
  「删断言凑行覆盖」——每个指标必须配 anti-gaming 说明；
- 看板的信任来自可核对：每个数值都标数据来源，抽查对得上才有公信力。

缺数据明示缺失，绝不编数。

## 3. 快速开始

```bash
cd architect/23_metrics_dashboard
./metrics_dashboard.sh apply     # 生成数据源：01 审计 + 03 门禁 + 13 flaky 检测
./metrics_dashboard.sh observe   # 渲染看板 → 抽查核对 3 项 → 诚实缺失演示
./metrics_dashboard.sh clean
```

实测输出（6 个指标，节选）：

```
- 自动化分层比例: unit:74.4% / integration:11.5% / e2e:12.2%
- 用例总规模: 418
- 金字塔形状判定: 过渡形态 ⚠️（偏 E2E）
- flaky 用例率: 40.0        ← 3 轮轻量检测的实测值
- SUT 数据层行覆盖率: 98
- 发布门禁状态: PASS
抽查 3 项全部与原始产物一致 ✅（验收线 ≥2）
```

## 4. 核心概念

### 4.1 指标字典三要素
**公式**统一口径之争（flaky 率的分母是用例数还是失败次数？字典说了算）；**来源**
是数据契约（文件路径+字段路径，兄弟项目改结构要同步字典）；**anti-gaming** 是对
指标被钻空子方式的预判与拆解。

### 4.2 看板是只读聚合器
采集器不产数据只读产物——01 审计产生分层比例、03 门禁产生覆盖率、13 产生 flaky 率。
数据生产与展示分离：看板挂了不影响生产，各项目的数据契约即看板的接口。

### 4.3 缺失明示是底线
数据源不存在时看板写「数据缺失（先跑 apply 生成）」而不是填 0——**0 和缺失是两种
完全不同的事实**，混用它们是数据造假的第一步。

## 5. 关键设计

| 设计 | 为什么 | 坑 |
|:---|:---|:---|
| 字典 yaml 而非硬编码 | 新增指标=加一行配置 | 指标没人消费就该删，字典不是垃圾场 |
| 来源路径相对仓库根 | 兄弟项目产物即接口 | 产物结构变更要同步字典——接口变更纪律 |
| 抽查断言进脚本 | 「看板可信」要可验证 | 人工看一眼的核对撑不过第二次汇报 |
| apply 生成数据源 | 前置项目的产物被 clean 后可再生成 | 轻量模式（13 用 3 轮）控制数据源成本 |

## 7. 深入要点

**Q1：DORA 四指标怎么接进来？** 部署频率/变更前置时长/变更失败率/MTTR——数据源是
流水线与工单系统（部署事件、PR 时间戳、事故工单）。接入方式与本实验同构：字典加
四行、采集器加数据源适配器。DORA 答「交付效能」，本实验 6 指标答「质量健康」，
两板合一面板才是完整的效能看板（项目 27 就是干这个的）。

**Q2：逃逸率怎么统计？** 逃逸缺陷 = 生产发现的、本可在测试阶段拦截的缺陷。分母用
「发布缺陷总数 = 测试发现 + 逃逸」，逃逸率 = 逃逸/总发布缺陷——分母不含「没发现
的缺陷」（没人知道它存在），口径必须写进字典。项目 26 的逃逸分析是它的定性版。

**Q3：自动化覆盖率怎么算才不造假？** 本实验用 collect-only 精确计数（字典里的
anti-gaming）：不是「自动化用例文件数/手工用例数」这种可刷指标，也标明统计时点。
更严格的口径是「需求覆盖」（每条需求至少一条自动化用例）——需要用例与需求的
映射表，成本高一档但抗 gaming 强一档。

**Q4：看板没人看怎么办？** 三个信号：指标没有 owner、数值三周没变化、没有因看板
引发的行动。看板的正确用法是**挂进例行机制**（周会第一页、发版前必查）——没人
消费的指标应该下架，这也是字典要能删的原因。

**Q5：度量会伤害团队吗？** 会，如果指标直接考核个人。反 gaming 的最后防线是
组织约定：度量用于定位系统性问题，不用于个人绩效——这条要写进字典的头部声明，
不是口头默契。

## 8. 总结

六个指标、三要素齐全、抽查一致、缺失明示——「质量怎么度量」从开放题变成一份
字典加一张静态页。非功能篇（20 压测/21 混沌/22 安全/23 度量）全部收官。下一篇
